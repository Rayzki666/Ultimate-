# 好好拍

一个装不进 App Store 也没关系的拍照助手——因为它是网页。

用 Safari 打开，「添加到主屏幕」，就和一个 App 没区别：全屏、有图标、离线也能开。
**不需要 Apple 开发者账号，不需要签名，不需要 TestFlight，不需要每七天重装一次。**

---

## 它想解决什么

不是「怎么把照片拍清楚」。是这两件事：

1. **拍出来的不是她想要的。** 通用摄影教程解决不了这个——她想要什么只有她知道。
   所以这里有一份**给她填的问卷**，填完生成一张只属于你们俩的「拍摄说明书」，
   之后 App 给的每一条建议都按她的答案来调。

2. **你们俩没有合照。** 因为每次总得有一个人站到镜头后面去。
   「合照」那一页专门解决这件事：手机怎么架、怎么求人、让孩子怎么拍、
   还有她说「今天不想被拍」时仍然可以拍的那一类。

技术只是承载。真正的解药在「她」和「话术」两页。

## 六个页面

| 页面 | 做什么 |
|---|---|
| **取景** | 实时取景教练。打开就一直在看：机身歪几度、镜头是俯是仰、光从哪边来、她在画面里站得对不对、**画面下沿有没有正好切在她的关节上**。一次**只给一条**最该改的，可以念出来。全部合格时亮绿灯。 |
| **配方** | 11 张场景卡：街边、咖啡馆、窗边、公园、海边、日落逆光、夜街、旅行、带孩子、阴雨天。每张卡都是能直接照做的动作。 |

## 取景教练在算什么

只做能算准的事，不猜。

**机身姿态（陀螺仪）**

`deviceorientation` 给的 β/γ 在手机接近竖直时会撞上万向节死锁——γ 会在 0 和 90 之间跳。
所以 `js/sensors.js` 先把欧拉角还原成**重力在机身坐标系里的方向向量**：

```
R = Rz(α)·Rx(β)·Ry(γ)
g = Rᵀ·(0,0,-1) = ( sinγ·cosβ , -sinβ , -cosγ·cosβ )
```

推导过程里 α 被消掉了，所以不需要指南针，相对方向就够；而这个向量是连续的，
在死锁区也不会跳。再从它算：

- **roll**（机身歪没歪）＝ 重力在屏幕平面内的投影与「屏幕正下方」的夹角，
  归一到最近的 90° 倍数，所以竖着横着倒着拿，0 都表示水平。
- **pitch**（俯仰）＝ `asin(-g.z)`。0 是水平指向前方，正数俯拍，负数仰拍。
  镜头快指向正上或正下时，重力几乎垂直于屏幕，这时「歪不歪」本身没有意义，就不报数。

俯仰角是这里面最有用的一个数，因为它对应一条很具体的规律：
**拍脸和半身要略微俯拍**（显脸小、显眼大），**拍全身要把手机放低**（显腿长）。
所以取景页有「全身 / 半身 / 特写 / 合照」四个档，选了哪个，俯仰角的合格区间就跟着变。

**画面（像素）**

把取景画面缩到 64×64，算亮度分布：平均亮度、高光死白比例、暗部死黑比例、
中央区域与外圈的亮度差（判逆光）、左右半边的亮度差（判光位）、色温倾向。

**一次只给一条**

按严重程度排序：曝光崩了 → 逆光 → 机身歪 → 俯仰角不对 → 站位 → 其它。
换提示还有 900 毫秒的迟滞，免得数字抖一下建议就跳一次。
拍照的时候人没空读列表，给三条等于没给。

**自动认人（关键点）**

点一下「认人」，MediaPipe 的 PoseLandmarker 会实时给出她身上 33 个关键点。
有了关键点，下面这些全部不用你操心：

- **站位**——她的头落在画面哪儿，离三分线差多少
- **头顶留白**——上面空太多就是把她压矮了
- **远近**——她在画面里太小，或者顶天立地
- **想拍全身却拍不到脚**——这个框根本装不下全身
- **肩线和身体朝向**——一边肩膀高，或者正面直对镜头（最显宽的角度）
- **合照时两个人之间的缝**
- **画面下沿有没有切在关节上** ← 这条只有拿到关键点才做得了

最后一条是这次升级里最有用的。切在大腿中段、腰、胸口都好看；
切在**膝盖、脚踝、手腕**上非常难看，而这件事在手机小屏幕上当场几乎看不出来，
回家放大才发现。现在它会直接告诉你：「下沿正好切在膝盖上，这是最难看的一刀。」

没点「认人」也能用——退回老办法：**点一下画面里她头的位置**，
站位和留白照样会判断，只是关节切割那条没有了。

**语音播报**

提示会念出来。这是「实时指导」里最要紧的一环：拍照的时候你的眼睛应该在她身上，
不是在手机屏幕上。只念真正要改的，而且两句之间至少隔 3.4 秒——
一个不停说话的手机比不说话更糟。在餐厅这种场合，点一下「语音」就关了。

**绿灯**

所有项都过了，画面四周会亮一圈绿边、震一下、说一句「可以按了」。
眼角余光就能看见，不用盯着读字。

反过来也成立：**没认出人、也没点过位置的时候，它不会说「可以按了」**——
那种情况下它并不知道她在哪儿，说了就是没根据。

## 装到 iPhone 上

### 一、开 GitHub Pages

仓库 **Settings → Pages → Source** 选 `Deploy from a branch`，
分支选 `main`、目录选 `/ (root)`，保存。等一两分钟，会给你一个地址：

```
https://<你的用户名>.github.io/<仓库名>/
```

> 摄像头必须在 HTTPS 下才能用。GitHub Pages 自带 HTTPS，所以这条自动满足。
> 如果你想在电脑上先试，`python3 -m http.server` 起在 `127.0.0.1` 也算安全上下文。

### 二、添加到主屏幕

用 **Safari**（不是微信、不是 Chrome）打开那个地址 →
底部「分享」→「添加到主屏幕」。

之后从主屏幕图标进入就是全屏的，没有地址栏，离线也能开。

### 三、给权限

- 第一次点「打开取景框」会问**相机**权限。
- 水平仪要**动作与方向**权限（iOS 13 之后必须由用户手势触发，所以是点按钮才问）。
  拒绝了也能用，只是水平和俯仰那两个数字会显示「未开」。
  想反悔：设置 → Safari → 动作与方向的访问。

## AI 点评（可选，不填也能用）

前五个页面**完全不需要联网、不需要 Key、不需要账号**。

想让 Claude 看照片，在「她」→「AI 点评」里填一个你自己的 Anthropic API Key
（[console.anthropic.com](https://console.anthropic.com/) 拿）。填完会先发一个几十 token 的
测试请求验证，通过了才存下来，免得拍完一天照片才发现 Key 填错了。

- Key 存在**这台设备的浏览器本地存储**里，不会同步、不会上传、不在仓库里。
- 请求**从你手机直接发到 `api.anthropic.com`**，中间没有任何服务器。
- 照片在发出前会缩到长边 1200px（Claude 标准档的上限是 1568px，再大只是白花视觉 token）。
  一张大约 1000 出头的视觉 token，按 Claude Opus 5 的价格算差不多**一张一分钱人民币量级**。
- Service Worker 只缓存本站的静态资源，**不碰发往 Anthropic 的请求**。

浏览器直连要带 `anthropic-dangerous-direct-browser-access: true` 这个请求头，
意思是「我知道我把 Key 放在了浏览器里」。

**这个取舍在这里成立，但别照搬到多人产品上。** Key 是你自己的、设备是你自己的、
页面是静态的、没有别人会用到这个页面上的 Key。一旦做成给别人用的东西，
Key 就必须放到服务端去。

点评的提示词里写死了一条：**只评摄影，不评人**。不评长相、身材、年龄、穿着，
也不试图辨认照片里是谁。评的是光、角度、构图、背景、清晰度、表情自然程度。

## 说清楚做不到的事

- **网页拿到的摄像头画面不是全画质。** `getUserMedia` 给的分辨率比原生相机低一截。
  所以这里的定位是**取景教练**，不是相机：调整好了，按「用系统相机拍」调起原生相机拍原图。
  拍完的照片会自动送到选片页。
- **清晰度是同一批里的相对比较**，不是绝对分。它算的是拉普拉斯方差，
  硬边缘多的画面天然得分高。同一个场景连拍出来的一批照片里挑糊的，非常准；
  跨场景比较则没有意义，所以标签上写的是「这批里」。
- **自动认人第一次要下载约 18MB**（WASM 运行时 12MB + 模型 5.6MB）。
  下载完存在 Service Worker 缓存里，之后离线也能用。不想下就别点「认人」，
  其余功能一点不受影响。
- **识别的是「人」，不是「她」。** 画面里有别人时，它认的是面积最大的那个。
  合照模式会同时看两个人。
- **语音依赖系统的中文发音**。iOS 自带，但如果系统里没有中文语音，它会用默认嗓音念，
  可能很怪——那就把语音关了。
- **陀螺仪读数在镜头几乎垂直朝上或朝下时不报水平角**，因为那时候这个量没有定义。
- **数据只在本机。** 清除 Safari 网站数据会把说明书和 Key 一起清掉。
  「她」→「关于与数据」里可以导出一份 JSON 备份。

## 文件结构

```
index.html                 六个页面的骨架
manifest.webmanifest       PWA 清单
sw.js                      离线缓存（改文件记得把 VERSION 加一位）
css/app.css                单手、暗光、竖屏
js/
  app.js                   路由与接线
  ui.js                    DOM 小工具、toast、震动
  store.js                 localStorage
  sensors.js               陀螺仪 → roll / pitch（含万向锁处理）
  frame.js                 亮度分布、逆光判定、清晰度
  coach.js                 取景教练：叠加层 + 提示优先级
  content.js               配方 / 话术 / 合照三页渲染
  survey.js                问卷 → 说明书 → 规则
  review.js                选片与复盘
  img.js                   EXIF 方向、缩放、base64
  claude.js                Claude 视觉点评（可选）
  vision.js                MediaPipe 姿态识别 + 关键点 → 拍照事实
  speak.js                 语音播报
data/
  recipes.json             11 张场景卡
  cues.json                33 句话术
  duo.json                 7 种合照方案
  survey.json              10 道题
icons/                     PWA 图标
vendor/mediapipe/          姿态识别的运行时（约 18MB，见 vendor/README.md）
```

没有构建步骤、没有 npm 依赖、没有 node_modules。改完直接推，Pages 自己会更新。

`vendor/` 里的文件是直接提交进仓库的，不从 CDN 拉。原因很直接：
MediaPipe 的官方模型挂在 `storage.googleapis.com` 上，**这个域名在中国大陆基本不可用**，
按官方示例写就是永远转圈。放同源顺带还解决了离线和第三方服务可靠性。
细节和更新方法见 `vendor/README.md`。
