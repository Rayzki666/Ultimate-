# AI 相机：实时摄影指导

## 产品目标

让不熟悉摄影的人，在真实拍摄过程中知道下一步该怎么做，并把调整后的画面直接拍下来。「最好」取决于想表达什么和被拍者的偏好，不用一个虚构的审美总分代替用户选择。

核心流程：选择想拍的范围 → 看到人物 → 解决最影响画面的问题 → 验证调整结果 → 等待稳定 → 拍摄 → 保存与复盘。

## 当前实现

首页用「看见好画面，也知道怎么拍」说明用途。主界面保留完整取景区，指导与快门放在取景区外，避免控件遮住将保存的画面。

- 顶部：实时状态、人物数量、光线与角度读数。
- 取景区：人物标记、网格、构图目标线。目标与所选构图一致，三分目标在一次拍摄过程中保持，不随人物跨越中心来回跳。
- 指导区：一句行动，例如「镜头往右转一点」；下面一行说明依据。一次只处理一件事。
- 检查项：光线、构图、角度，区分通过、调整、待测。小进度条表示连续稳定时间，不是照片质量评分。
- 快门：始终保留人工决定拍摄时机的能力。绿灯是建议，不锁住快门。拍后留在相机，可继续拍。
- 相册入口：本次页面会话照片，进入选片再下载。没有假称保存到系统相册，也没有默默删除超量照片。

当前通过本机人物关键点、像素和角度信号给出指导。没有调用实时云端视觉模型。所谓识别指的是检测人体位置，不是判断身份。

## 从「能指导」到「懂摄影」的后续设计

### 场景理解

为自然人像、旅行环境人像、亲子动作、合照提供意图选择。模型只在用户启用后，稀疏读取小尺寸画面；返回可验证的场景观察和候选动作，例如换角度避开头后方的杂物。不得把上传帧或云端费用隐藏在「开启相机」里。

连续高频判断继续在本机完成。云端回答必须带对应帧时间与场景标识，旧回答不能覆盖新画面。当人走动或镜头转向时，立即丢弃旧的背景建议。

### 个性化摄影指导

把现有问卷中的偏好转成明确的拍摄意图，例如人物占比、环境留白、自然抓拍或正式构图。偏好影响候选建议，而不是给身体和外貌打分。可允许上传参考照片，但要区分风格参考与承诺复刻。

### 拍摄时机与选片

在真机数据验证后，再加入眨眼、动作峰值、运动模糊估计与短连拍。默认仍由用户按快门。选片应解释同场景照片中的具体差异，并保留用户最终选择。

### 画质与实时性能

如目标是与系统相机同等级的拍摄控制，需要评估原生 iOS/Android 相机接口。网页版本适合验证指导体验，视频帧输出不能代替原生全分辨率拍照。

当前姿态检测在主线程限频执行，且只处理新视频帧。MediaPipe 官方说明该 API 是同步调用；下一轮应把检测移入 Worker，并用真机帧耗时和响应延迟决定采样频率，不能只靠桌面测试判断流畅度。

## 关键行为约束

1. 没有新鲜画面或没有检测到人物，不显示就绪。
2. 手动标记不等于跟踪，不能用它判断连续稳定。
3. 合照少于两个人，不显示就绪；两个人都参与裁切与稳定检查。
4. 暖色、肩线或正面姿态不作为拍摄失败条件。
5. 新错误立即撤销绿灯；语音不堆积过期建议。
6. 前置的屏幕坐标、测光坐标和保存镜像保持一致。
7. 离开相机、切换后台、权限迟到返回都不能让摄像头偷偷重启。
8. 模型加载完成仅说明模型可用，不能提示「认出人了」。
9. 拍摄与查看不触发任何 AI 点评上传。

## 真机验收（尚需执行）

- iPhone Safari 与 Android Chrome：首次相机/动作权限，同意与拒绝均可恢复。
- 明亮窗边、逆光、弱光：建议方向正确，光线恢复后退出错误状态。
- 人物移动、人物短暂遮挡、进入第三人：不沿用已失效的就绪状态。
- 前置和后置：移动方向、镜像、测光位置与保存结果一致。
- 全身/半身/特写/合照 + 三分/居中/自由：偏好切换后重新判定。
- 连续开关相机、加载模型途中离开页面、锁屏返回：不残留媒体轨道或模型。
- 360 像素宽屏、系统字体放大、横屏：快门可访问，不被导航遮挡。
- 实拍图片确认裁切、分辨率、下载行为和画质；模拟相机测试不能替代这一项。
